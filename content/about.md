## 博客介绍

### 这是什么

星野笔记（Starlog）是一个托管在 GitHub Pages 或 Cloudflare Pages 上的静态博客。它保留静态站点加载快、成本低、版本可追踪的优点，同时提供登录、在线编辑、评论和 Pull Request 投稿等协作能力。

博客以 Markdown 文件为中心：文章源码保存在 content/posts/，关于页保存在 content/about.md。每次发布都会产生 Git 提交，因此正文、元数据和历史版本可以一起追溯；站点构建时读取这些文件并生成文章页面。

### 内容如何组织

| 内容 | 用途 | 常见入口 |
| :--- | :--- | :--- |
| 首页 | 按置顶状态与日期浏览公开文章，查看摘要、标签、字数和预计阅读时间 | 导航栏“首页” |
| 归档 | 按年份回顾文章，适合查找较早内容 | 导航栏“归档” |
| 标签 | 按主题筛选文章 | 导航栏“标签” |
| 文章页 | 阅读正文、查看目录、复制源码、发表评论和浏览历史 | 首页文章卡片 |
| 帮助页 | 了解博客、写作语法、部署方式和安全边界 | 导航栏“帮助” |

文章页会为二至四级标题生成目录和锚点。点击标题旁的链图标可以复制小节链接；打开带有标题锚点的地址时，页面会自动滚动到对应位置。

### 从哪里开始

- 只想阅读：从首页开始，使用 ⌘/Ctrl + K 或 / 搜索标题、摘要、标签和正文。
- 想写文章：进入“写文章”，先填写标题、日期、标签和摘要，再在编辑区写 Markdown。
- 想贡献内容：登录 GitHub 后直接发布；没有目标仓库写权限时，使用“申请发表 (PR)”提交 Pull Request。
- 想了解实现：先阅读本页“技术介绍”，再查看仓库中的 README.md、src/lib/ 和 src/components/。

## 使用指南

### 浏览、搜索与复制

首页卡片显示标题、日期、摘要、标签、字数和预计阅读时间，置顶文章会排在普通文章之前。归档页按年份分组，标签页可以筛选同一主题的内容。

搜索操作：

1. 按 ⌘/Ctrl + K，或在非输入框区域按 / 打开搜索。
2. 输入关键词；搜索会匹配标题、摘要、标签和正文。
3. 使用 ↑、↓ 选择结果，按 Enter 打开，按 Esc 关闭。

文章标题下的“复制”菜单提供四种结果：

| 选项 | 说明 |
| :--- | :--- |
| 复制链接 | 当前文章的完整地址 |
| 直接复制源码 | 原样复制正文，保留本站和洛谷扩展语法 |
| 复制洛谷源码 | 将交互展示框按默认值转换为静态 Markdown |
| 复制基本源码 | 继续把合并表格、折叠框和 Tuack 表格转换为普通 Markdown |

转换只作用于剪贴板内容，不会改动仓库中的原文。

### 登录、评论与权限

选择“登录”后，博客会使用 GitHub OAuth Device Flow：浏览器打开 GitHub 验证页，输入设备码并确认授权。令牌只保存在当前浏览器，可以在 GitHub 授权管理页随时撤销。

文章底部的评论区需要 GitHub 登录。评论支持常用 Markdown、公式和代码预览，内容保存到目标仓库的 GitHub Discussions，因此可跨浏览器、跨设备查看。登录用户可以删除自己的评论，仓库管理员可以按 GitHub 权限管理评论。旧版本遗留的本机评论会标记为“仅本机旧评论”，不会自动上传。

### 写作、预览与本地草稿

进入“写文章”后，可以在“仅编辑、双栏、仅预览”之间切换。双栏模式会尝试同步编辑区和预览区的滚动位置；如果希望分别滚动，可在设置中关闭同步。

- 停止输入约 2.5 秒会自动保存草稿。
- 点击“保存草稿”，或按 ⌘/Ctrl + S 可立即保存。
- 工具栏可插入标题、引用、列表、链接、代码块、公式、Tuack 表格和展示框模板。
- 下载按钮可导出当前文章为 .md 文件。
- 图片按钮会把本地图片上传到 public/uploads/，并插入图片 Markdown；上传需要 GitHub 写权限。
- 文章信息支持标题、slug、日期、更新日期、标签、封面、摘要、草稿和置顶状态。

本地草稿使用浏览器 localStorage 保存。设置页可以导出全部草稿或清空草稿；清除站点数据会同时删除草稿、未同步评论和本地偏好。

### 发布、投稿与历史版本

1. 有目标仓库写权限时，编辑器直接向配置的分支提交 Markdown。
2. 没有写权限时，选择“申请发表 (PR)”会创建分支或 Fork，并向目标仓库提交 Pull Request。
3. 管理员在“内容管理 → 发表申请”中检查、合并或关闭投稿。

GitHub Actions 或 Cloudflare Pages 会在提交后自动构建。文章页的“历史”按钮会列出对应 Markdown 文件的 Git 提交；选择版本可查看当时的内容，“版本对比”可逐行查看新增和删除。历史版本点击“编辑”时，如果没有完全相同的文章，系统会新建一份草稿，避免覆盖当前版本。

### 加密文章

管理员可以在“文章信息”中勾选“发布为带密码的加密文章”。标题和标签保留在公开 frontmatter 中，正文及其他文章信息在浏览器内使用 PBKDF2-SHA-256 派生密钥，再用 AES-256-GCM 加密后提交。

- 标签不加密，所以加密文章仍会出现在标签云和搜索结果中。
- 密码不会上传 GitHub、写入 URL 或保存到浏览器；本设备只在 IndexedDB 保存不可导出的 CryptoKey。
- 清除站点数据、换设备或文章重新加密后，通常需要再次输入密码。
- 解锁后编辑会先保存为明文本地草稿，重新发布时再次加密；发布成功后会清理该草稿。
- 忘记密码且没有可用设备密钥时，站点维护者也无法恢复正文，请自行保管密码。

### 外观、字体与仓库设置

设置页提供深浅色主题、全站字号（80%–130%）、字体优先级和背景渐变强度。偏好默认保存在浏览器，并在同一浏览器的其他标签页同步；完成 GitHub 授权后，还可以保存与账号关联的偏好。

“目标仓库”决定直接发布、PR 投稿、图片上传和历史读取的位置，包含 GitHub 用户或组织、仓库名、分支和文章目录。修改前请确认账号拥有需要的权限。

### 编辑器快捷键

| ⌘/Ctrl + S | 保存本地草稿 |

## Markdown 语法手册

本站支持 CommonMark、GitHub Flavored Markdown（GFM）、KaTeX，以及下面的扩展指令。代码围栏中的内容只会原样显示，不会执行扩展语法，适合写教程和展示示例。

### Frontmatter 文章头信息

文章文件顶部用 YAML frontmatter 描述元数据：

~~~yaml
---
title: "文章标题"
date: "2026-10-04"
updated: "2026-10-05"
summary: "文章摘要"
tags: ["数学", "前端"]
cover: "https://example.com/cover.jpg"
draft: false
pinned: false
author: "作者名"
---
~~~

标题、日期和标签用于文章卡片与详情页；摘要留空时会从正文截取；draft: true 隐藏文章；pinned: true 将文章排在首页前面。文件名默认对应 URL slug，例如 content/posts/hello.md 对应 /posts/hello。

### 标题、段落与强调

~~~markdown
# 一级标题
## 二级标题
### 三级标题

普通段落中的 **粗体**、*斜体*、***粗斜体***、~~删除线~~ 和行内代码。

---
~~~

页面会为二至四级标题添加目录项。相邻的普通文本属于同一段落，空行用于开始新段落；反斜杠可以转义 Markdown 符号。

### 列表、任务与表格

~~~markdown
- 无序项目
  - 缩进子项目
- [ ] 未完成任务
- [x] 已完成任务

1. 有序项目
2. 第二项

| 左对齐 | 居中 | 右对齐 |
| :--- | :---: | ---: |
| A | B | C |
~~~

表格单元格中可以使用强调、链接、行内代码和公式；长表格会在窄屏上提供横向滚动。

### 链接、图片、引用与代码

~~~markdown
[链接文字](https://example.com "可选标题")
![替代文字](https://example.com/image.png)

> 这是引用，可以写成多行。

~~~ts
const hello = (name: string) => \`你好，\${name}\`
~~~
~~~

外部链接会在新标签页打开，代码块会自动高亮并提供复制按钮。编辑器上传图片后会自动插入图片语法。

### 脚注、自动链接与换行

~~~markdown
第一行末尾加两个空格即可在同一段落内换行。

<https://example.com> 会自动成为链接。

这是带脚注的文字。[^note]

[^note]: 脚注内容可以写在文章任意位置。
~~~

### 数学公式（KaTeX）

行内公式使用一个美元符号，独立公式使用两个美元符号：

~~~markdown
行内公式：$E = mc^2$。

$$
\\int_{-\\infty}^{\\infty} e^{-x^2}\\,\\mathrm{d}x = \\sqrt{\\pi}
$$
~~~

支持 aligned、矩阵、分段函数等常用 LaTeX 环境。

### 合并单元格与 Tuack 表格

表格中让单元格内容仅为 ^ 可与上方合并；内容仅为 < 可与左侧合并：

~~~markdown
| 测试编号 | 数据范围 | 特殊性质 |
| :---: | :---: | :---: |
| 1 | $n \\le 10$ | 无 |
| 2 | ^ | 无 |
| 3 | 跨列合并示例 | < |
~~~

在表格前单独写 ::cute-table{tuack} 可启用三线表样式。

### 折叠提示框（Callout）

提示框由至少三个冒号开始和结束，类型可以是 info、note、tip、success、warning、error 或 danger。标题放在方括号，{open} 会默认展开：

~~~markdown
:::info[提示标题]{open}
提示框内容支持 **Markdown**、公式和代码。
:::

:::warning[注意]
请先保存草稿。
:::
~~~

提示框可以嵌套；内层使用更多冒号并用不少于开启数量的冒号关闭。

### 交互展示框

展示框使用 ::show_begin{标题}{变量定义} 和 ::show_end 包围。变量之间用分号或逗号分隔：

| 简写 | 类型 | 示例 | 控件 |
| :---: | :--- | :--- | :--- |
| Z | 整数 | n:Z=2[-5,5,1] | 数字输入框 + 滑动条 |
| Q | 有理数 | p:Q=0.5[-2,2,0.25] | 数字输入框 |
| S | 字符串 | name:S=Starlog[0,12] | 文本输入框 |

给 Q 定义末尾加 {faster_set} 可启用滑动条。占位符包括：*&show(变量)*& 输出当前变量，*&hs(表达式)*& 计算数值表达式，&*floor()*& 和 &*ceil()*& 按小数位取整，*&变量:{键,内容}*& 建立文字映射。

~~~markdown
::show_begin{二次函数}{a:Z=1[-2,2,1]; b:Q=0.5[-2,2,0.25]{faster_set}}
当前 $a^2+b$ = *&hs(a^2+b)*&。
::show_end
~~~

展示框会在渲染前替换为对应值，因此可放在正文、表格和公式附近；未在标题中声明但出现在映射里的变量会自动创建控件。

## 技术介绍

### 总体架构

项目采用 React 19、TypeScript、Vite 和 Tailwind CSS。入口 src/main.tsx 挂载应用，src/App.tsx 使用 React Router 定义首页、文章、归档、标签、帮助、登录、管理后台和编辑器路由。

| 层次 | 主要目录或依赖 | 职责 |
| :--- | :--- | :--- |
| 页面 | src/pages/ | 组合业务流程和路由页面 |
| 组件 | src/components/ | Layout、Markdown、目录、搜索、评论、提示框等可复用 UI |
| 数据与业务 | src/lib/ | 文章解析、GitHub API、认证、加密、主题和本地存储 |
| 内容 | content/ | 关于页和文章 Markdown |
| 静态资源 | public/、src/assets/ | 上传图片、图标和站点资源 |

### 内容与渲染流程

1. Vite 通过 import.meta.glob 读取 content/posts/**/*.md 原始源码。
2. frontmatter 解析器分离元数据和正文，文章构造器计算 slug、摘要、标签、字数和阅读时间。
3. ReactMarkdown 配合 remark-gfm、remark-math、rehype-katex 和 rehype-highlight 渲染正文。
4. rehype-slug 为标题生成锚点，extractToc 用同样规则生成目录；展示框和提示框内的标题会排除。
5. usePosts 合并仓库文章与浏览器本地草稿；同名明文草稿不会覆盖仓库中的加密文章。

### GitHub 与部署

项目提供两条部署路线：

- Cloudflare Pages：构建命令为 npm run build，输出目录为 dist。内置 functions/login/[[path]].ts，OAuth 中转与页面同源，不需要额外 relayUrl。
- GitHub Pages：将 Pages Source 设为 GitHub Actions。工作流会根据仓库名设置 base path（本仓库为 /Blog/），并复制 index.html 为 404.html 处理 SPA 刷新；此路线需要单独部署 oauth-relay/ Worker。

~~~bash
npm install
npm run dev        # 本地开发
npm run build      # 类型检查与生产构建
npm run preview    # 预览 dist
~~~

### 配置与 OAuth

站点信息集中在 src/lib/config.ts。githubConfig 控制用户、仓库、分支和文章目录；oauthConfig 控制 Client ID、权限范围和中转地址。

GitHub OAuth 使用 Device Flow（RFC 8628），浏览器不保存 client secret。由于 GitHub 授权端点不提供浏览器可读取的 CORS 响应头，前端通过 Pages Function 或 oauth-relay Worker 转发请求；中转只负责透传并补充 CORS 响应，不持有仓库令牌。

### 数据保存与安全边界

- 公开文章、关于页和历史版本以 Git 文件为准，Git 提交记录提供审计线索。
- 登录令牌、草稿和外观偏好保存在浏览器；清除站点数据会移除它们。
- 直接发布和图片上传都需要 GitHub API 写权限；公开仓库默认使用 public_repo，私有仓库需改为 repo。
- 加密文章使用浏览器 Web Crypto；服务器只看到标题、标签和密文。
- 请勿把 client secret、个人访问令牌或文章密码提交到仓库。公共电脑使用完毕后应退出登录。

### 目录结构速查

~~~text
.
├── content/
│   ├── about.md                 # 本帮助页
│   └── posts/*.md               # 文章源码
├── functions/login/[[path]].ts  # Cloudflare Pages OAuth 中转
├── oauth-relay/                 # GitHub Pages OAuth Worker
├── public/uploads/              # 编辑器上传的图片
├── src/components/              # Markdown、目录、评论、搜索等
├── src/lib/                     # 解析、认证、GitHub API、加密
├── src/pages/                   # 页面与编辑器
└── .github/workflows/deploy.yml # GitHub Pages 部署
~~~

## 常见问题

### 为什么刷新文章页会出现 404？

GitHub Pages 需要 404.html 作为 SPA 路由兜底；项目构建时会自动复制 index.html。自建服务器则需要把未知路径回退到 index.html。

### 发布后为什么没有立刻更新？

GitHub Actions 或 Cloudflare Pages 需要安装依赖、构建并部署，通常需要 1–2 分钟。可以在仓库的 Actions 或 Pages 部署记录中查看状态。

### 为什么本地草稿会消失？

草稿依赖浏览器 localStorage。隐私模式、清除站点数据、切换浏览器或设备都会使当前草稿不可见。重要内容请定期导出或发布。

### 为什么 OAuth 需要中转？

GitHub 授权端点不返回浏览器可读取的 CORS 响应头，纯前端无法直接读取 Device Flow 响应。Pages Function 和 oauth-relay Worker 都只做请求转发，不保存机密。

### 加密文章忘记密码怎么办？

密码不会上传，设备密钥也不能导出为密码。没有正确密码或仍可用的设备密钥时，正文无法恢复；请在发布前使用密码管理器保存密码。

### 可以直接粘贴个人访问令牌吗？

建议使用 OAuth Device Flow：权限范围更清楚，令牌可在 GitHub 设置中撤销，也不需要把高权限 token 粘贴到网页。调试时若临时使用令牌，请确保不写入源码、日志或提交记录。
